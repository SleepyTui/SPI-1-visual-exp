# Rain Pond · 三皮肤 Live 测试实验

需要 Node.js 22 或更新的 LTS。进入 `demos/rain-pond/` 后运行 `npm ci` 安装锁定的依赖，再运行 `npm run dev`，访问 http://127.0.0.1:4176。首次点击「开始聆听」解锁浏览器音频。依赖、构建产物和测试截图不纳入仓库。

## 实现顺序与模块边界

1. `src/domain.js`：独立逻辑池塘、特殊表面、带种子的降雨过程、音高范围、节律与和声。没有 UI 或 Web Audio 依赖。
2. `src/audio.js`：唯一 `SoundEntity`，持有时钟、生成器、声部、混音与效果器。基于 [Tone.js](https://github.com/Tonejs/Tone.js/) 的 Web Audio 组件。水面 10 声部、荷叶 2 声部、浅碟 4 声部；所有声音都来自雨滴命中，没有另行播放的背景 track。预留声音结束时间，达到声部上限的命中会保留为静音视觉事件。
3. `src/controls.js`：统一参数映射、多输入按住状态、鼠标、键盘、双指及 XY 触摸条。皮肤不拥有交互状态。
4. `src/renderer.js`：三套视图投影、素材缓存和 Canvas 2D 动画；仅消费声音事件与参数，不修改音符过程。特殊表面用局部坐标登记命中点，以匹配不同皮肤的叶和碟。
5. `src/main.js`：GUI、参数存储/导入/导出、调试视图。切换皮肤仅更换渲染和视觉参数；`SoundEntity` ID、生成器种子、音频节点、音符序列保持连续。

命中事件包含 `id / time / x / y / material / midi / velocity / audible / chord`。时间来自 Web Audio 时钟。音频提前调度，视觉按照同一个落地时间推进。手势改变后续生成的雨滴，已经在空中的事件保持原目标。

## 三个视觉方向

- 雾蓝透明：生成的干净池面素材保留原稿透明渐层与池岸；独立 SVG 叶、浅碟在加载时栅格缓存；亮核、圆头雨与椭圆涟漪动态绘制。
- 曲水版画：干净曲水底图保留岸草、纸纹和套印边；叶和浅碟采用同色系 SVG 素材；雨线与断环实时绘制。
- 程序随笔：池塘、叶、浅碟、雨与涟漪均为路径，使用蓝色线条与特殊命中的珊瑚色响应。

`public/assets/reference-*.png` 是工作区已定稿图片的副本。顶部「对照定稿」可直接比较。两个生成的背景已复制进工程；提示和来源见 `ASSETS.md`。图片没有烘焙雨、水波、命中或文字。**不是把一张含雨的静态定稿当作运行画面。**

## 操作对照

| Web 输入 | 作用 | 设备端对应 |
| --- | --- | --- |
| 池面按住拖动 | 临时加雨并移动雨区 | 触摸按住滑动 |
| Alt 拖动、方向键 | 仅移动 | XY 移动输入 |
| 滚轮、Shift 横拖、＋／－ | 缩放雨区 | 双指拉开／合拢 |
| 双指触屏 | 中点移动、间距缩放 | 双手联动 |
| 左侧 Y、下侧 X 条 | 单轴移动 | 纵／横触摸条 |
| 聚雨垫、空格 | 临时加雨，松开恢复 | 触摸门控 |

默认基础雨量 50%，雨区 82%，76 BPM，雨密 62%，节律感 68%。基础雨量设零可测试按住降雨。雨区为零时停止生成。雨区 100% 时进入全池覆盖。荷叶命中偏好仅在雨区覆盖其表面时生效，不会从雨区外偷偷补低音。

音符雨滴与无音符氛围雨分开：Playground 中将「氛围雨数量」设为 0，可只观察音符过程。Console 的灰色事件因节奏、冷却或声部上限而不触发声音。

## Playground 与 Console

Playground 提供雨尾、滴径、下落时长、不透明度、氛围雨数量、波环层数、寿命、扩散范围、扁平度、线宽、断环、溅起、物体响应、画面缩放、纵向投影、纹理、颜色、网格、雨区、命中标注、绘制数量和帧率上限。每个滑条配数值输入，三套皮肤分别保存。可以还原单个皮肤或导入导出全部配置。

Console 显示音频实体 ID、音频时钟、生成步、事件序号、当前和声、各声部累计发声次数、电平、画布缓冲、绘制耗时、最近输入映射及命中列表。电平表带平滑，暂停后的实际静音由未平滑波形检查。

## 嵌入式迁移边界

本实验使用 Canvas 2D，没有 WebGL 或 Three.js。Web Audio / Tone.js 是声音适配器，设备端可让现有 DSP 接收同一类音符与控制事件；它不要求移植浏览器音频库。绘制层的静态背景和 SVG 可以预先栅格化，动态部分使用线段、弧、点和少量变换，并设置事件数量上限。画面预算不足时优先保留接近命中时刻的事件，再裁减旧视觉；声音调度不受画面帧率影响。

320×320 模式只把实际 Canvas 缓冲设为 320，检查像素层次、字体与稀疏/密集时的可读性。桌面加载的源图片和缓存仍不是 MCU 资源格式；Canvas 也不能直接移植成设备 API。固件中需按现有绘图库实现渲染适配，并实测 DMA/CPU、带宽与脏区刷新。

参考资源估算（不是实测）：320×320 单张 RGB565 背景为 200 KiB；同尺寸 ARGB8888 单缓冲为 400 KiB，双缓冲为 800 KiB。一个 160×96 RGBA 叶片约 60 KiB，一个 96×56 RGBA 浅碟约 21 KiB；可进一步按透明度格式和设备存储方式取舍。无需在 MCU 内保留全部高分辨率 PNG 或全部皮肤的展开纹理。

## 验证

`npm test`：种子一致性、落点与雨区、特殊表面优先、低音间隔、雨密、门控、多输入、皮肤坐标投影与局部表面登记。

`npm run test:browser`：先启动本地服务器，再运行浏览器测试。首次使用先运行 `npx playwright install chromium`，测试默认使用 Playwright 的 Chromium；也可通过环境变量 `PLAYWRIGHT_BROWSER_PATH` 指向已有 Chromium 兼容浏览器。报告与截图存放于 `test-output/`。`node tests/timbres.mjs` 用同样方式检查三种音色和荷叶发声。

`npm run build`：生成 `dist/`。实际听感仍需用户通过音箱或耳机试听；本次没有访问或烧录硬件。
